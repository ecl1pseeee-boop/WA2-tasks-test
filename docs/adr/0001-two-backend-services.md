# 1. Два сервиса (PHP и Python) вместо одного

## Контекст
Проект был взять с Курса 1, где студентам требовалось научиться работать с
двумя фреймворками, научаться связывать их работу. Это был Laravel (SSR) +
Python(FastApi) (REST + Websocket). Реальной нагрузки, которая требовала бы 
масштабирования - не было. 

## Решение
Оставляем разделение как есть: `php` отдаёт HTML-страницы через nginx →
FastCGI (аутентификация, объявления, комментарии), `api` отдаёт JSON
(`/api/feed`, `/api/health`) и держит WebSocket (`/api/ws`) через nginx →
HTTP-прокси. 

## Отвергнутые альтернативы
- Один сервис на Laravel, отдающий и страницы, и JSON-API. Технически
  это возможно: Laravel умеет REST и WebSocket (через отдельный пакет), 
  но задание Курса 1 требовало показать оба стека отдельно, а не потому 
  что архитектура Boardy этого требует.
- Один сервис на FastAPI, отдающий и SSR, и API. Отвергнут по той же
  причине — курс требовал именно PHP для серверных страниц.

## Следствия
Два процесса, два образа, два деплоя вместо одного. Оба должны видеть
одни и те же данные → пришлось делить одну базу напрямую,
что создаёт скрытую связанность между сервисами. При текущей нагрузке
Boardy это скорее перебор: мы платим за поддержку двух сервисов, а требования,
которое оправдывало бы разделение нет, не сформулировано ни разу. Разделение
объясняется историей проекта, а не текущими требованиями Виктора.

## Статус
Принято (унаследовано с Курса 1). На этой неделе не пересматриваем —
фиксируем состояние, а не меняем его.
