# 3. Вход: сессии + GitHub OAuth, без JWT

## Контекст
Виктор явно потребовал сохранить вход через GitHub. Приложение `php` полностью
серверный рендеринг (SSR): страницы, формы, ни одного SPA-фронтенда,
которому нужен был бы отдельный токен.

## Решение
Аутентификация целиком на стороне Laravel: обычный логин по паролю
и вход через GitHub. Оба способа сходятся
в одной точке — `Auth::login($user)` — и используют одну и ту же таблицу
`users`; GitHub-пользователь ищется/создаётся по e-mail. 
`SESSION_DRIVER=database`, то есть сессии тоже
лежат в общей MySQL. У `api` (FastAPI) аутентификации нет вообще —
`/api/feed`, `/api/health` и `/api/ws` открыты без проверки, кто стучится.

## Отвергнутые альтернативы
- JWT вместо серверных сессий. Осмысленно для API с несколькими
  клиентами или SPA, которому нужно носить токен самому. У Boardy весь
  UI — серверный рендеринг, отдельного клиента нет. Не взяли, тк это
  добавило бы сложность (хранение/ротация токена) без единой причины,
  которая бы это оправдывала.
- Отдельная таблица пользователей для GitHub-входа. Развели бы логику
  на два источника правды. Не взяли — вместо этого GitHub-профиль
  сведён к тем же `users` через e-mail как ключ связи.

## Следствия
Простая, стандартная для Laravel-SSR схема — ровно то, что просил
Виктор. Но: `api` полностью открыт —
`/api/feed` и WebSocket доступны кому угодно без токена и без пароля.
Это проблема, которая уже зафиксирована в `TECH_DEBT.md`
